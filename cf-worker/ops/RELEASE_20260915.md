## New database initialization

- `0000_initial_schema.sql` bootstraps empty databases. Never run it blindly to reconcile an existing production database.
- Frozen migrations `0001`–`0007` were not edited.
- Wrangler 4.131.1 `d1 migrations apply` split the CASE-containing payment trigger in `0003_payments.sql`, failing with `incomplete input` after 0000–0002.
- Recovery used whole-file `d1 execute ... --remote --file migrations/0003_payments.sql --yes` on the NEW empty database.
- Every expected table, index, trigger and seeded plan was compared against an isolated database built through 0003. Only then was the missing 0003 ledger entry registered. Remaining migrations applied successfully.
- Final remote snapshot verified all canonical object definitions, eight migration ledger entries and zero users before cutover. `tools/verify-remote-schema.mjs` makes object verification repeatable; it does not silently update any ledger.
- On another database: stop at any migration failure; inspect actual objects and compare to the appropriate migration prefix. Do not blindly mark a migration complete or rerun ALTER statements.

The old database had payment structures beyond its ledger. Their presence was verified; the exact historical operator/command is unknown. Reset did not erase this discrepancy from the audit trail or pretend the ledger had been correct.

## Ownership and constraints

- `users`: identity, credential hash and activation status.
- `sessions` + `session_contexts`: opaque hashed token, expiry, revocation, server-assigned web/app purpose. Unclassified sessions receive no authority.
- `app_device_bindings`: composite (user_id, device_id), account-scoped ownership, three active bindings enforced by triggers. Installation identifier is not hardware attestation.
- `devices`: legacy reference only. Not used as current web identity or new APP count.
- `user_glossaries`, `usage_logs`: user-owned business records; all added routes scope queries by authenticated user_id.
- Payment orders, notifications, membership grants and usage settlement retain existing idempotency/ownership constraints. Payment test plans/prices were not invented or changed during the reset.
- New schema initialization vs canonical tables, FK lists, indexes, triggers and plans is an automated test.
