## 2. 优先问题与证据

### G01 / P0：术语整库覆盖没有保留跨端字段（已复现）

证据：`cf-worker/src/index.ts` 的 glossary PUT 仅保留 source/target/category/folder/enabled；`cf-worker/src/account/data.ts` 的术语新增生成 id/note，删除按 id 查找。APP 的 `MainViewModel.GlossaryEditor.cs` 上传整库且 DTO 不携带网页 id/note。

复现：网页 API 创建带备注的词条 → APP 风格 PUT 整库 → 网页 API 读取时 id/note 消失 → 原 id 删除返回 404。当前网页 UI 编辑本身仍是本机存储，因此不能声称所有网页点击都会产生此问题；这是两套已存在云端 API 的真实不兼容。

计划：先确定统一字段与稳定 ID、兼容旧无 ID 数据；增加乐观并发版本（updated_at/ETag），过期写入返回冲突；先导出备份与冲突预览，禁止静默覆盖。不能只给客户端增加一个确认框就宣称避免了跨端数据丢失。

验收：APP→Web→APP round-trip 保留全部字段；两个客户端同时修改不互相吞数据；旧数据可读；原删除 ID 仍有效；每个账号隔离。

### H01 / P1：翻译结算到网页历史的写入链路缺失（已复现）

证据：Worker translate 结算 `translation_requests` 和 `usage_monthly`；网页 history 读取 `usage_logs`。当前源码/数据库触发器未找到该翻译链路向 usage_logs 的写入。历史测试通过手工 INSERT 构造记录，绕开了生产写入链路。

复现：隔离 APP 会话翻译“法兰”，上游模拟返回 Flange → HTTP 200、扣费字符数 2、月用量 2 → 同账号 Web 历史为空。

计划：新增最小可测试记录适配层，确保每个 request_id 只生成一次历史，记录语言/字符数/状态/时间，不上传图纸或全文。需要先确定结算与记录的一致性策略；不能简单在结算后追加一个可能重复/失败的 INSERT。历史损坏不能导致重复扣费。

验收：成功/部分成功/失败/超时/幂等重放/跨月/账号隔离；成功产生记录且重试不重复。记录只描述文字翻译，不伪造 DWG 下载。

### G02 / P1：术语数量限制与校验不一致（代码确认）

`/v1/glossary` 和 APP 下载上限 1000；`/v1/terminology` 新增上限 5000。前者还静默截断长字段，后者对超长输入拒绝。云端可能形成 APP 无法下载的词库。

计划：统一容量/长度契约；容量变更必须兼容现有 >1000 数据，不能删除多余词条。明确分页或明确错误，保留原数据。

验收：999/1000/1001/5000 边界；超长与空白字段不静默丢失；错误格式可被两端展示。

### G03 / P1：网页“同步”只是拉取合并，编辑没有上传（代码确认）

`D:\DWGC2E_Website\js\terminology.js` commit 写账号隔离 localStorage，syncGlossary 调用 list 并合并；没有在编辑保存时调用 create/remove。APP 上传和下载也均为手动操作。

计划：先明确 UI 文案“保存到此浏览器 / 从云端读取”，然后在统一 G01/G02 契约后增加显式上传、冲突预览、取消和重试。不要把本机成功提示写成云端成功。

验收：两个浏览器与 APP 的保存位置清晰；网络断开保留草稿；失败不显示云端成功；重复操作不增加重复词条。

### R01 / P1：版本与下载发行链路未闭环（本地+线上确认）

- 官网 site-config：1.0.0，现有蓝奏云下载入口；本次未验证该远程安装包版本。
- Worker 本地配置和线上 `/v1/version`：2.1.0，download_url 为空。

- 本地版本高于公开版本不自动等于错误：本地构建尚不代表公开发行获授权。问题在于尚无明确一致的发行清单与验证门槛。

计划：生成候选 manifest 与版本对照表（不自动上线）；经授权选定可公开包、校验哈希与平台标识，再同时维护网站/Worker/清单；验证 APP 清单失败的 Worker 回退以及无下载时明确提示。

### S01 / P1：网页会话存储与早期设计存在差异（代码确认，非已证实漏洞）

网页 api-client 读取 sessionStorage Bearer，会话服务按哈希认证；并不是早期设计中的 HttpOnly Cookie/BFF。sessionStorage 不等于直接泄漏，但同源脚本执行风险面不同。

计划：明确选型与威胁模型；覆盖 XSS/CSP、会话变更和 401；若迁移 Cookie，必须一并设计 CSRF、SameSite、跨端 APP Bearer 兼容及分阶段回滚，不能只改 token 存储位置。

### S02 / P1：Pages→Worker 的限流来源需要真实链路验证（待验证风险）

Pages 代理只转发白名单头，CF 反馈以 CF-Connecting-IP 限流。没有在本轮确认 Worker 实际看到的客户端地址语义，不应假设与浏览器真实 IP 一致，也不可直接转发任意 X-Forwarded-For。

计划：脱敏观测来源，设计可信代理鉴别后再转发；测直达 Worker/官网代理/伪造头/多用户共用出口，避免全站共享限流桶或信任伪造地址。
